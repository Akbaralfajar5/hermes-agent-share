# Seminar Hasil Skripsi Presentation (Sidang Akhir)

## When This Applies
User has completed their skripsi (all BAB I-V) and needs a **final defense presentation** (seminar hasil / sidang akhir). This is NOT a proposal — the research is DONE and results are available.

## Differences from Seminar Proposal

| Aspect | Proposal | Hasil |
|--------|----------|-------|
| Research status | Planned (BAB I-III) | Completed (all BAB) |
| Data slides | None | Results per RM with statistics |
| Methodology detail | Described | Shown with actual execution evidence |
| Timeline | Future phases | Already completed |
| Committee focus | Feasibility of plan | Validity of findings |
| Theory slides | Required (Landasan Teori) | **Skip** — committee already read it |

## Standard Slide Structure (11-13 slides)

| # | Slide | Content |
|---|-------|---------|
| 1 | **Cover** | Judul, nama, NIM, prodi, universitas, pembimbing I+II, penguji, tahun |
| 2 | **Pendahuluan** | Full title + brief context (what was done) |
| 3 | **Rumusan Masalah** | Research questions (numbered, color-coded cards) |
| 4 | **Penelitian Terdahulu** | Prior studies table + position of this research |
| 5 | **Metode Penelitian** | Research design, samples, instruments, analysis methods |
| 6 | **Prosedur Penelitian** | ADDIE phases / research flow (actual execution) |
| 7–9 | **Hasil per RM** | One slide per research question with data, tables, statistics |
| 10 | **Simpulan & Saran** | Conclusions + recommendations (school, students, future researchers) |
| 11 | **Demo / Produk** | Live website/product demo (if applicable) |
| 12 | **Terima Kasih** | Closing with pembimbing info |

**Note:** Landasan Teori is deliberately omitted. User correction: "Untuk sidang ga perlu ada teori kali, langsung aja." Committee already read the proposal; go straight to Rumusan Masalah → Penelitian Terdahulu → Metode → Results.

## Result Slides Pattern

Each RM result slide should follow this structure:
1. **Big stat callout** — the headline number (e.g., "93.87% SANGAT LAYAK") in a large colored card
2. **Breakdown** — per-validator or per-indicator scores in aligned rows/cards
3. **Statistical test** — t-value, p-value, df in a compact box (if applicable)
4. **Conclusion bar** — one-line green banner summarizing the finding

### Data Display Best Practices
- Use progress bars for percentage comparisons (filled rounded rects)
- Pre/Post comparison: show both scores + gain + % increase in a row of stat cards
- T-test results: compact card with t-hitung, p-value, df, and H₀ decision
- Color code: blue for pre-test, green for post-test, gold for gain, orange for %

## Key Pitfalls
- **Don't include timeline** — research is done, timeline is irrelevant
- **Don't over-explain methodology** — committee already approved it in proposal
- **Show evidence** — include dates, sample sizes, actual data collection photos if available
- **Match BAB IV structure** — each result slide should map to a BAB IV sub-section
- **N-Gain vs Gain Score** — some dosen reject N-Gain for non-cognitive variables. Use simple Gain Score (Post − Pre) unless told otherwise.
- **Skip Landasan Teori** — user explicitly corrected: "ga perlu ada teori, langsung aja." The only exception is if dosen penguji specifically requests theory content.
